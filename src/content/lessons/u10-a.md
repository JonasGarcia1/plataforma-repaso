## Concepto

Spring Framework ofrece un contenedor de objetos y herramientas para web, datos y transacciones. Spring Boot organiza dependencias, autoconfiguración y arranque sobre Spring. Un starter reúne dependencias habituales; no es una anotación mágica que implementa las reglas del negocio.

Un bean es un objeto gestionado por el contenedor. IoC significa que el framework controla parte de su creación y ciclo de vida. La inyección de dependencias entrega a un objeto sus colaboradores. Preferir el constructor hace visibles los requisitos y permite probar la clase sin arrancar Spring.

El scope singleton es el predeterminado: una instancia por definición de bean y contenedor, no una instancia universal de la clase. Prototype crea instancias al solicitarlas; request y session existen en contextos web. Un singleton con estado mutable sigue necesitando cuidado con concurrencia.

## Ejemplo

Fragmento parcial Java 21 / Spring Boot 3; falta la implementación del puerto:

```java
interface Inventario {
    boolean disponible(String sku);
}

@Service
class CrearPedido {
    private final Inventario inventario;

    CrearPedido(Inventario inventario) {
        this.inventario = inventario;
    }

    boolean puedeCrear(String sku) {
        return inventario.disponible(sku);
    }
}
```

Con un único constructor no hace falta @Autowired. Si existen dos beans compatibles, debemos elegir explícitamente con @Qualifier o @Primary.

## En entrevista

**Pregunta:** ¿Qué agrega Spring Boot sobre Spring Framework?

**Breve:** Spring provee capacidades; Boot configura muchas de ellas según el classpath y las propiedades.

**Ampliada:** usaría @Configuration y @Bean para objetos de bibliotecas externas, y component scanning para componentes propios. Mantendría configuración del entorno fuera del código y secretos fuera del repositorio.
## Error frecuente

Crear un servicio con new y esperar que tenga inyección, proxies o @Transactional activos. El contenedor solo interviene sobre los objetos y llamadas que gestiona.

## Práctica

Necesitás un inventario simulado en desarrollo y uno real en producción. Proponé cómo seleccionarlos sin cambiar CrearPedido.

### Pista

El caso de uso depende de una interfaz; la selección corresponde a configuración.

### Solución

Definí adaptadores con perfiles separados, por ejemplo @Profile("local") y @Profile("prod"), y activá el perfil desde el entorno. Probá que solo uno queda registrado. Los perfiles no son un almacén de secretos.

## Profundización

@ConfigurationProperties agrupa propiedades tipadas y permite validarlas. Inyectar prototype dentro de singleton no lo recrea en cada llamada automáticamente: la resolución suele suceder al construir el singleton. Si necesitás resolución posterior, evaluá ObjectProvider y justificá el caso.
