## Concepto

Los genéricos permiten expresar relaciones entre tipos y detectar errores antes de ejecutar. `List<Pedido>` declara qué admite la lista; evita casts repetidos y asignaciones equivocadas. Un método `<T> T primero(List<T> datos)` relaciona el tipo recibido con el devuelto.

Los genéricos son invariantes: `List<Integer>` no es subtipo de `List<Number>`. Si lo fuera, alguien podría insertar un `Double` en una lista que promete contener solamente enteros. Los wildcards permiten formular contratos más flexibles sin perder esa protección.

La regla PECS ayuda: producer extends, consumer super. `? extends Number` permite leer elementos como `Number`, pero no agregar números arbitrarios; `? super Integer` permite agregar enteros, aunque al leer solo podemos asegurar `Object`. No son instrucciones sobre el sentido de herencia de una clase concreta: describen límites de un tipo desconocido.

## Ejemplo

Java 21 ejecutable como `Genericos.java`:

```java
import java.util.*;
class Genericos {
    static <T> void copiar(List<? extends T> origen,
                          List<? super T> destino) {
        for (T elemento : origen) destino.add(elemento);
    }
    public static void main(String[] args) {
        List<Integer> reservas = List.of(2, 3);
        List<Number> auditoria = new ArrayList<>();
        copiar(reservas, auditoria);
        System.out.println(auditoria); // [2, 3]
    }
}
```

El método expresa una relación: todo lo producido por el origen debe poder consumirse en el destino. El compilador determina un tipo compatible.

## En entrevista

**Respuesta breve:** los genéricos hacen reutilizable el código con chequeo estático; `extends` sirve para productores y `super` para consumidores.

**Respuesta ampliada:** el borrado de tipos elimina gran parte de los parámetros genéricos del código ejecutable, aunque quedan metadatos en ciertos lugares. No puedo usar `new T()` ni comprobar `obj instanceof List<String>`. Puedo verificar `List<?>`, pero eso no prueba los tipos de sus elementos.

## Error frecuente

Usar tipos raw como `List` para «simplificar»: se pierden verificaciones y los errores pueden aparecer tarde como `ClassCastException`. Tampoco existen `List<int>`; usá el wrapper `Integer`.

## Práctica

Diseñá una función que sume cualquier lista de subtipos de `Number` sin modificarla.

### Pista

La función solo consume la lista como fuente de números.

### Solución

La firma puede ser `static double sumar(List<? extends Number> valores)`. Acumulá `valor.doubleValue()`. Esto admite enteros y doubles, pero no garantiza precisión monetaria: una suma financiera debería acordar `BigDecimal` y reglas de redondeo.

## Profundización

Un límite como `<T extends Comparable<? super T>>` permite ordenar tipos cuyo contrato de comparación acepta el propio tipo o alguno de sus padres. Leelo por partes; agregar comodines sin una necesidad concreta empeora la API.
