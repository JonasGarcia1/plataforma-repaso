## Concepto

Una transacción agrupa cambios con propiedades ACID: atomicidad, consistencia de invariantes, aislamiento y durabilidad. El aislamiento controla qué interferencias pueden observar operaciones concurrentes. No significa que toda transacción vea siempre el mismo mundo: depende del nivel y del motor.

Un índice es una estructura auxiliar que acelera ciertos accesos a cambio de espacio y trabajo al escribir. EXPLAIN muestra el plan elegido; el beneficio depende de selectividad, distribución de datos y estadísticas. Agregar un índice a cada columna suele ser contraproducente.

PL/SQL es el lenguaje procedural de Oracle. Los procedimientos expresan operaciones y pueden entregar resultados mediante parámetros OUT; las funciones devuelven un valor. Un cursor recorre resultados, pero una operación SQL sobre conjuntos suele ser más simple y eficiente si resuelve el mismo trabajo.

## Ejemplo

Primer fragmento: PostgreSQL, diagnóstico que no ejecuta la consulta:

```sql
EXPLAIN
SELECT id, estado FROM pedidos WHERE cliente_id = 42;

CREATE INDEX idx_pedidos_cliente ON pedidos(cliente_id);
```

Segundo fragmento: Oracle PL/SQL, función independiente del ejemplo anterior:

```sql
CREATE OR REPLACE FUNCTION doble(p_valor NUMBER)
RETURN NUMBER IS
BEGIN
  RETURN p_valor * 2;
END;
/
-- Invocación Oracle:
SELECT doble(3) FROM dual;
```

Crear el índice es una modificación de esquema que se practica en una base de laboratorio.

## En entrevista

**Pregunta:** ¿Cómo investigarías una consulta lenta sin adivinar la causa?

**Breve:** optimizo a partir del plan y de mediciones; uso transacciones para proteger operaciones relacionadas.

**Ampliada:** compararía filas estimadas y reales, scans, joins y tiempos. EXPLAIN ANALYZE ejecuta la sentencia en PostgreSQL: no lo usaría a ciegas sobre escrituras de producción.
## Error frecuente

Afirmar que las subconsultas siempre son lentas, que una función se invoca siempre con CALL o que los procedimientos impiden SQL injection si internamente concatenan SQL dinámico.

## Práctica

Dos compradores leen stock 1 e intentan descontar uno. Proponé una escritura que no permita stock negativo.

### Pista

Uní condición y modificación en la base.

### Solución

UPDATE productos SET stock = stock - 1 WHERE id = ? AND stock > 0. Si afecta una fila, la reserva se logró; si afecta cero, no. Agrupá esta operación y la creación del pedido en la transacción apropiada.

## Profundización

Un cursor explícito en Oracle sigue OPEN, FETCH y CLOSE; un cursor FOR loop administra ese ciclo. Elegí procesamiento fila a fila solo cuando una transformación por conjuntos no sea suficiente. No mezcles sintaxis Oracle, MySQL y PostgreSQL sin identificar el dialecto.
