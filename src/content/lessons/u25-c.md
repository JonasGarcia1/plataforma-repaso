# Kafka Streams y procesamiento con estado

## Concepto

Kafka Streams es una biblioteca Java para construir aplicaciones que leen, transforman y publican flujos de registros Kafka. Una topología conecta fuentes, transformaciones y destinos; la aplicación se ejecuta como un proceso propio y Kafka aporta particionado, transporte y topics internos. No se instala una lógica de Streams dentro del broker.

Un `KStream` representa una secuencia de eventos: cada registro cuenta como una ocurrencia. Un `KTable` representa el estado más reciente por key, por lo que una actualización reemplaza el valor anterior de esa key en la vista lógica. Una tabla puede construirse a partir de un topic compactado, aunque la compactación es asíncrona y el topic conserva offsets con posibles huecos.

Las operaciones con estado, como agregaciones, joins y ventanas, necesitan almacenar datos localmente. Kafka Streams crea topics de changelog y repartición cuando hacen falta para recuperar estado o alinear claves. La key determina la partición y, por lo tanto, qué tarea puede procesar registros relacionados manteniendo el orden de esa partición. Un cambio de key puede provocar repartición y costo de red.

Las ventanas agrupan registros por tiempo, pero hay que elegir qué reloj usar y qué hacer con eventos tardíos. El tiempo de evento describe cuándo ocurrió en el dominio; el tiempo de procesamiento describe cuándo llegó al proceso. Una ventana con grace period espera cierto margen de retraso; luego una llegada tardía puede ignorarse según la política. No existe un valor correcto para todos los negocios.

## Ejemplo

Para contar pedidos por cliente en ventanas de cinco minutos, la topología usa `customerId` como key, agrupa por esa clave, aplica una ventana y materializa el resultado en un store consultable. Debe definirse si un pedido que llega tarde actualiza el conteo y cuánto tiempo se conservan los datos.

```java
builder.stream("orders.created")
    .groupByKey()
    .windowedBy(TimeWindows.ofSizeAndGrace(
        Duration.ofMinutes(5), Duration.ofMinutes(1)))
    .count(Materialized.as("orders-by-customer"));
```

El fragmento ilustra la topología; producción requiere configuración de aplicación, serializadores y recuperación del estado.

## En entrevista

**Pregunta:** ¿Qué estado mantiene Kafka Streams y cómo se recupera tras perder una instancia?

**Breve:** Kafka Streams puede guardar estado local asociado a particiones y respaldarlo en changelog topics para restaurar una instancia.

**Ampliada:** Diseñaría keys para que los datos relacionados queden en la misma partición, elegiría ventanas y retención según la regla de negocio y observaría la restauración. Al fallar una instancia, otra puede asumir particiones y reconstruir estado desde el changelog.
## Error frecuente

Adoptar Streams para un consumer que solo valida y guarda cada evento, o confundir `KTable` con una tabla SQL completa. Streams agrega estado, topics internos, operaciones de despliegue y decisiones de tiempo; debe responder a una necesidad de transformación continua.

## Práctica

Diseñá una agregación de pedidos por cliente y ventana. Identificá la key, el resultado materializado, un evento tardío, una clave inválida y cómo reconstruirías el estado después de borrar el directorio local.

### Pista

Preguntá qué garantiza la partición y qué información debe persistir fuera de la memoria del proceso.

### Solución

Usá el identificador estable del cliente como key, especificá ventana y grace period según el retraso tolerable, y materializá el store. El state store local se respalda mediante changelog topics; al reiniciar, Streams puede restaurarlo desde Kafka. Definí métricas y política de errores para detectar restauración lenta o eventos fuera de política.

## Profundización

La configuración `processing.guarantee` puede usar `at_least_once` o `exactly_once_v2`, según versiones y topología. Exactly-once de Streams coordina lecturas, escrituras Kafka y offsets dentro de su frontera; no vuelve atómica una llamada externa a SQL, HTTP o correo. Evaluá requisitos de replicación y costo del clúster antes de habilitarla.
