## Concepto

Archivos, sockets y conexiones representan recursos externos. El recolector de basura administra memoria, pero no garantiza cerrar oportunamente esos recursos. Un descriptor abierto de más puede agotar límites aunque todavía haya memoria disponible.

`try-with-resources` cierra automáticamente objetos que implementan `AutoCloseable`, tanto si el bloque termina bien como si lanza una excepción. Si declarás varios recursos, se cierran en orden inverso. El alcance del bloque muestra durante cuánto tiempo querés poseer el recurso.

Si falla el trabajo y además falla `close`, la excepción del trabajo permanece como principal y la del cierre se agrega como suprimida. Podés verla con `getSuppressed()`. Si solamente falla el cierre, ese fallo se propaga. Un `finally` manual que lanza otra excepción o retorna puede ocultar lo ocurrido en el bloque original.

## Ejemplo

Java 21 ejecutable como `Recursos.java`:

```java
class Recursos {
    static class Sesion implements AutoCloseable {
        private final String nombre;
        Sesion(String nombre) { this.nombre = nombre; }
        @Override public void close() {
            System.out.println("Cierra " + nombre);
        }
    }
    public static void main(String[] args) {
        try (var primero = new Sesion("primero");
             var segundo = new Sesion("segundo")) {
            System.out.println("Procesa pedido");
        }
    }
}
```

Se imprime primero el procesamiento, luego el cierre de segundo y finalmente el de primero. En recursos anidados esto permite cerrar dependencias antes que su soporte.

## En entrevista

**Respuesta breve:** uso try-with-resources para que la vida del recurso sea explícita y el cierre ocurra también ante errores.

**Respuesta ampliada:** primero identifico quién es dueño del recurso. No cierro una conexión o stream compartido que pertenece al llamador si el contrato no me autoriza. Crear recursos por fuera del bloque sin un manejo cuidadoso puede dejar fugas si falla una inicialización posterior.

## Error frecuente

Pensar que `finally` garantiza ejecución bajo cualquier circunstancia imaginable. La terminación abrupta del proceso puede impedirlo. La garantía de cierre se aplica al flujo normal de ejecución de la JVM, no a una máquina apagada.

## Práctica

Una lectura lanza `IOException("lectura")` y su cierre lanza `IOException("cierre")`. Identificá la excepción principal y cómo inspeccionar la otra.

### Pista

Try-with-resources conserva el primer fallo del trabajo.

### Solución

La principal es «lectura». La de «cierre» aparece entre los elementos de `principal.getSuppressed()`. Conservar la excepción completa, en lugar de registrar solo su mensaje, ayuda a no perder esa información diagnóstica.

## Profundización

No todo objeto `Stream` necesita cierre, pero los streams vinculados a I/O, como `Files.lines`, sí. Un stream creado desde una lista no posee un archivo abierto que liberar.
