## Concepto

Los patrones nombran soluciones recurrentes. Elegí uno solo cuando aclara un problema de creación; para un caso chico, un constructor o una función puede alcanzar.

- **Singleton:** una instancia por contexto; evitá usarlo como estado global.
- **Factory Method:** una subclase decide qué producto crear.
- **Abstract Factory:** crea una familia de objetos compatibles.
- **Builder:** arma un objeto con opciones legibles.
- **Prototype:** parte de un objeto existente para crear una variante.

El nombre es útil para conversar; el propósito y el costo son más importantes que memorizar la definición.

## Ejemplo

Java 21, ejemplos mínimos e independientes.

```java
enum Configuracion { INSTANCIA } // Singleton simple

record Solicitud(String sku, int unidades) {
    static class Builder {
        private String sku; private int unidades = 1;
        Builder sku(String v) { sku = v; return this; }
        Builder unidades(int v) { unidades = v; return this; }
        Solicitud build() { return new Solicitud(sku, unidades); }
    }
}

record Plantilla(String asunto) {
    Plantilla copiarCon(String nuevo) { return new Plantilla(nuevo); }
}
```

`Builder` evita constructores largos; `copiarCon` expresa Prototype sin usar `Cloneable`. Una fábrica podría devolver distintos `Aviso` según el canal, y una abstract factory coordinar aviso y formato de cada canal.

## En entrevista

**Respuesta breve:** Builder ordena construcción, Prototype copia una configuración y una fábrica encapsula qué objeto corresponde crear.

**Respuesta ampliada:** empezaría por el motivo. Si la creación varía por canal y esas variantes comparten una familia, una fábrica puede ayudar. Si solo hay dos valores fijos, un `switch` simple puede ser más claro.

## Error frecuente

Llamar Factory Method a cualquier método estático `of`, o creer que Singleton significa una instancia en todo un sistema distribuido. Su alcance depende del cargador o contenedor.

## Práctica

Debés construir una solicitud de dos libros y copiar una plantilla cambiando el asunto. ¿Qué usarías?

### Pista

Separá construir por pasos de partir de un objeto existente.

### Solución

`new Solicitud.Builder().sku("LIBRO").unidades(2).build()` usa Builder. `plantilla.copiarCon("Pedido enviado")` aplica Prototype. Elegiría una fábrica solo si hay una decisión real de creación que convenga ocultar.

## Profundización

Validá invariantes al terminar el Builder y definí si una copia debe ser superficial o profunda. Un patrón no reemplaza validación ni pruebas.
