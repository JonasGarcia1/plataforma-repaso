## Concepto

`Optional<T>` representa un resultado que puede estar presente o ausente. Es especialmente útil como retorno de búsquedas: obliga al consumidor a pensar qué significa no encontrar. `map` transforma un valor presente, `flatMap` evita Optional anidados y `orElseGet` calcula un reemplazo solo si hace falta.

`orElse` evalúa su argumento aunque el valor exista. `get` sin comprobar presencia puede lanzar una excepción. Optional no debería contener `null`, y un método que declara devolver Optional tampoco debería devolver `null`. No lo uses automáticamente para todo campo o parámetro; muchas APIs y herramientas tienen expectativas distintas.

En fechas, `LocalDate` representa una fecha sin hora; `LocalDateTime`, fecha y hora sin zona; `Instant`, un punto de la línea temporal. `ZonedDateTime` combina fecha, hora y reglas de zona. `Duration` mide tiempo transcurrido; `Period` expresa cantidades de calendario. Un día civil no siempre dura 24 horas en zonas con cambios horarios.

## Ejemplo

Java 21, clase completa compilable:

```java
import java.time.*;
import java.util.Optional;
class Entregas {
    static LocalDate fechaLocal(Clock reloj, ZoneId zona) {
        return LocalDate.now(reloj.withZone(zona));
    }
    static String nombreVisible(Optional<String> nombre) {
        return nombre.map(String::strip)
            .filter(texto -> !texto.isEmpty())
            .orElseGet(() -> "Cliente sin nombre");
    }
    public static void main(String[] args) {
        Clock fijo = Clock.fixed(Instant.parse("2026-09-16T02:00:00Z"),
                                 ZoneOffset.UTC);
        System.out.println(fechaLocal(fijo, ZoneId.of("America/Argentina/Buenos_Aires")));
        // 2026-09-15 en esta zona
    }
}
```

Inyectar un reloj permite probar medianoches y vencimientos sin depender de la hora real del equipo.

## En entrevista

**Pregunta:** ¿Qué expresa `Optional` y cuándo no conviene usarlo?

**Breve:** Optional hace explícita la ausencia; los tipos temporales separan fechas locales de instantes globales.

**Ampliada:** guardaría el instante de creación de un pedido como `Instant` y calcularía su presentación con una zona acordada. Una fecha de cumpleaños suele ser `LocalDate`; agregarle UTC sin necesidad cambia el significado del dato.
## Error frecuente

Usar `LocalDateTime` como si identificara inequívocamente un instante mundial. Sin zona u offset puede ser ambiguo, especialmente durante cambios de horario.

## Práctica

Una búsqueda devuelve Optional vacío y el fallback consulta otro servicio. Elegí `orElse` u `orElseGet` y explicá cómo probarías una expiración.

### Pista

Separá evaluación diferida de control del tiempo.

### Solución

Usá `orElseGet` para ejecutar la consulta solamente ante ausencia. Para expiración, pasá un `Clock.fixed` y probá antes, exactamente en el límite y después. Definí si el instante de vencimiento ya cuenta como expirado.

## Profundización

Al recibir fechas como texto, acordá formato y zona. ISO-8601 reduce ambigüedades, pero escribir una fecha con formato estándar no resuelve por sí solo qué zona de negocio corresponde.
