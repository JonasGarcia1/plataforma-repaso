## Concepto

Serializar transforma datos en una representación transportable; deserializar reconstruye una estructura a partir de ella. JSON expresa objetos, arrays y valores simples. XML utiliza elementos y atributos, admite namespaces y puede validarse con esquemas. Ninguno conoce automáticamente las reglas de nuestro negocio.

Un DTO es un objeto diseñado para transferir datos. Separarlo de la entidad persistida evita exponer campos internos, referencias circulares o relaciones que disparan consultas inesperadas. Un DTO de entrada tampoco debe permitir al cliente elegir su rol administrativo o el precio que decide el servidor.

Jackson y Gson son bibliotecas para trabajar con JSON. Jackson también dispone de módulos para XML y tipos de fecha. En aplicaciones Boot 3, Jackson suele integrarse mediante los convertidores HTTP; la configuración efectiva depende de las dependencias y personalizaciones del proyecto.

## Ejemplo

Fragmento parcial Java 21 con Jackson 2; ObjectMapper debe configurarse antes de compartirlo:

```java
record PedidoDto(String sku, int quantity) {}

ObjectMapper mapper = new ObjectMapper();
PedidoDto pedido = new PedidoDto("BOOK-42", 2);
String json = mapper.writeValueAsString(pedido);
PedidoDto copia = mapper.readValue(json, PedidoDto.class);
// {"sku":"BOOK-42","quantity":2}
```

Con Gson el equivalente es gson.toJson(pedido) y gson.fromJson(json, PedidoDto.class). Esa conversión no garantiza quantity > 0: la validación es otro paso.

## En entrevista

**Pregunta:** ¿Por qué una API suele intercambiar DTO en vez de entidades?

**Breve:** serialización convierte un objeto a un formato; un DTO delimita los datos permitidos en ese intercambio.

**Ampliada:** elegiría contratos estables, fechas con formato explícito y valores monetarios con BigDecimal. Verificaría cómo se tratan campos desconocidos, valores nulos y compatibilidad al agregar campos.
## Error frecuente

Confundir JSON con la serialización nativa de Java mediante Serializable. También es incorrecto asumir que deserializar datos externos es seguro sin límites de tamaño, validación y configuración.

## Práctica

La entidad Usuario contiene id, email, passwordHash y rol. Diseñá una respuesta pública y una entrada de registro.

### Pista

Los dos mensajes tienen objetivos distintos; no comparten necesariamente campos.

### Solución

Respuesta: id y email. Entrada: email y contraseña, enviada por HTTPS y procesada con hash seguro en el servidor. Nunca devolver passwordHash ni permitir que el registro público elija el rol.

## Profundización

Para XML externo deshabilitá resolución de entidades externas cuando corresponda al parser elegido. Para JSON evitá activar deserialización polimórfica irrestricta. Probá compatibilidad de contratos con ejemplos antiguos y nuevos, no solamente un recorrido objeto → JSON → objeto.
