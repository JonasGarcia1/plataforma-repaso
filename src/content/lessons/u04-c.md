## Concepto

Una función recursiva resuelve una entrada usando versiones más pequeñas del mismo problema. Necesita un caso base y progreso hacia él. Java no garantiza optimización de llamadas de cola; demasiada profundidad puede producir `StackOverflowError`.

Un árbol representa jerarquías de nodos. En un árbol binario de búsqueda, valores menores y mayores se separan según el criterio. Buscar cuesta O(h), siendo h su altura: un árbol equilibrado puede tener altura logarítmica; uno degenerado parece una lista. DFS explora ramas y BFS niveles. Sus colas o pilas tienen costo de memoria.

Un heap binario conserva una relación de prioridad entre padre e hijos, sin ordenar totalmente todos los elementos. `PriorityQueue` expone primero el menor según su comparador. Insertar y extraer cuestan O(log n); consultar la cabecera, O(1). Iterar la cola no devuelve necesariamente los elementos en orden.

## Ejemplo

Java 21, fragmentos para colocar dentro de una clase:

```java
static long factorial(int n) {
    if (n < 0 || n > 20) {
        throw new IllegalArgumentException("Rango admitido: 0..20");
    }
    return n <= 1 ? 1 : Math.multiplyExact(n, factorial(n - 1));
}

static long factorialIterativo(int n) {
    if (n < 0 || n > 20) {
        throw new IllegalArgumentException("Rango admitido: 0..20");
    }
    long resultado = 1;
    for (int i = 2; i <= n; i++) resultado *= i;
    return resultado;
}
```

Ambos tienen tiempo O(n). La versión recursiva usa O(n) pila; la iterativa, O(1) espacio auxiliar. Para factoriales mayores, `BigInteger` evita el límite de `long`, pero no vuelve gratuito el cálculo.

## En entrevista

**Pregunta:** ¿Qué diferencia hay entre un árbol binario de búsqueda y un heap?

**Breve:** distingo estructura jerárquica, árbol de búsqueda y heap; no asumo que toda estructura arbórea está equilibrada.

**Ampliada:** en un factorial aclaro que 0! = 1 y que negativos quedan fuera del dominio. En producción prefiero la versión que haga claros límites y consumo de recursos; recursión suele ser natural para árboles, no necesariamente para una multiplicación lineal.
## Error frecuente

Llamar «pila» al heap de prioridad. Una pila de datos es LIFO; un heap mantiene una propiedad de prioridad. El heap de memoria de la JVM es otro concepto distinto.

## Práctica

Tenés prioridades `[4,1,3]`. Cargalas en `PriorityQueue<Integer>` y sacalas hasta vaciarla. Probá además factorial de 0, 5 y 21.

### Pista

Usá `poll()` mientras la cola no esté vacía.

### Solución

Las extracciones devuelven 1, 3 y 4. `factorial(0)` devuelve 1; `factorial(5)`, 120; `factorial(21)` se rechaza explícitamente en lugar de entregar un número desbordado.

## Profundización

En un recorrido de un árbol de n nodos, visitarlos todos cuesta O(n), incluso si está equilibrado. El equilibrio mejora ciertas búsquedas, no elimina el trabajo de procesar cada nodo.
