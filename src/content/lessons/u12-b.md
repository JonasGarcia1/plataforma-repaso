## Concepto

JPQL consulta entidades y atributos, no tablas y columnas. Spring Data permite consultas derivadas y @Query para expresar casos más específicos. Una proyección devuelve solo los datos necesarios, útil para pantallas o APIs que no necesitan modificar entidades completas.

Page contiene elementos e información total que puede requerir una consulta de conteo; Slice indica si hay más resultados sin exigir ese total. La paginación debe usar un orden determinista: si varias filas empatan, agregá una clave única como desempate.

N+1 aparece cuando una consulta inicial provoca una consulta adicional por cada resultado, por ejemplo al acceder al cliente de cada pedido. Se detecta midiendo SQL, no mirando solo el número de métodos Java.

## Ejemplo

Fragmento parcial Spring Data JPA / Java 21; Pedido tiene id, estado y total:

```java
interface PedidoResumen {
    Long getId();
    BigDecimal getTotal();
}

interface Pedidos extends JpaRepository<Pedido, Long> {
    @Query("""
        select p.id as id, p.total as total
        from Pedido p
        where p.estado = :estado
        """)
    Page<PedidoResumen> resumir(
        @Param("estado") String estado, Pageable pageable);
}

// En el servicio:
var pagina = repositorio.resumir("CREATED",
    PageRequest.of(0, 20, Sort.by("id")));
```

La proyección reduce datos transferidos. El tipo de estado debe coincidir con el modelo real; si es enum, el parámetro también debe serlo.

## En entrevista

**Pregunta:** ¿Cómo detectarías y resolverías un problema N+1 en JPA?

**Breve:** solucionaría N+1 seleccionando deliberadamente los datos o asociaciones necesarias.

**Ampliada:** consideraría proyecciones, fetch join, entity graphs o batch fetching según el caso. Mediría consultas y filas: eliminar N+1 a costa de un producto cartesiano gigantesco tampoco es una mejora.
## Error frecuente

Aplicar fetch join de una colección junto con paginación sin revisar el SQL y la estrategia del proveedor; puede producir paginación en memoria o resultados problemáticos.

## Práctica

Una página de 20 pedidos ejecuta una consulta inicial y 20 consultas de cliente. ¿Cuántas consultas hay y qué cambio probarías?

### Pista

El problema lo dispara el acceso repetido a una asociación.

### Solución

Hay 21 consultas. Para una tabla de lectura probaría una proyección que seleccione id de pedido y nombre de cliente con join. Verificaría el resultado y el número de consultas en una prueba con varios clientes.

## Profundización

La paginación por offset puede ser costosa en páginas profundas. La paginación por cursor usa la última clave ordenada como punto de continuación. Requiere diseñar el contrato y el orden, no cambiar arbitrariamente la respuesta a mitad de una API existente.
