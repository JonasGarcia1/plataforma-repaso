## Concepto

En arquitectura por capas separamos presentación, aplicación y persistencia. Es una organización útil, pero el dominio puede terminar dependiendo de detalles de base de datos si las dependencias se dirigen siempre hacia la infraestructura.

La arquitectura hexagonal propone puertos y adaptadores. El núcleo expresa casos de uso y reglas; los puertos describen interacciones necesarias y los adaptadores conectan HTTP, JPA, Kafka o pruebas. El nombre no impone seis interfaces. El objetivo es cambiar un detalle externo con impacto acotado.

Un puerto de entrada expresa una operación disponible; uno de salida expresa una capacidad requerida, como reservar stock. El adaptador de entrada traduce solicitudes y llama al caso de uso. Un adaptador de salida implementa el contrato con una tecnología concreta.

## Ejemplo

Fragmento parcial Java 21, núcleo sin Spring:

```java
interface StockPort {
    boolean reservar(String sku, int cantidad);
}

class CrearPedido {
    private final StockPort stock;
    CrearPedido(StockPort stock) { this.stock = stock; }

    void ejecutar(String sku, int cantidad) {
        if (cantidad <= 0) throw new IllegalArgumentException();
        if (!stock.reservar(sku, cantidad)) {
            throw new IllegalStateException("Sin stock");
        }
    }
}
```

Un adaptador JDBC o un fake de test implementa StockPort. La configuración Spring ensambla el caso de uso con el adaptador apropiado.

## En entrevista

**Breve:** hexagonal protege reglas de negocio detrás de contratos y deja tecnologías en adaptadores.

**Ampliada:** ubicaría interfaces según la necesidad del núcleo, no copiaría automáticamente cada método del ORM. Testearía el caso de uso con un fake y verificaría el adaptador mediante integración.

## Error frecuente

Crear carpetas domain/application/infrastructure y mantener imports de controllers o repositorios JPA dentro del dominio. La separación se comprueba en dependencias, no en nombres.

## Práctica

Un caso de uso construye HttpClient, llama al proveedor y decide si aceptar un pedido. Separá sus responsabilidades.

### Pista

El negocio necesita una respuesta, no conocer headers ni URLs.

### Solución

Definí un puerto ConsultarDisponibilidad con un resultado de negocio. El caso de uso decide aceptación. Un adaptador HTTP maneja transporte, serialización y timeouts, traduciendo fallos a resultados o errores definidos por el contrato.
