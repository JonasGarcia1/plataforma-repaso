## Concepto

Una anotación agrega metadatos. `@Override` ayuda al compilador; una anotación propia puede ser leída por procesadores o por reflexión. `@Retention` decide si se conserva en código fuente, archivo de clase o ejecución. `@Target` restringe dónde se aplica. Poner `@Auditar` no registra nada por sí mismo: necesitás una herramienta que interprete ese metadato.

Lombok genera código durante compilación: constructores, accesores o builders, según las anotaciones. Reduce escritura repetitiva, pero el equipo debe entender qué genera. Un `@Data` indiscriminado puede exponer setters o igualdad inadecuada en entidades; revisá también cómo aparecen objetos relacionados en `toString`.

Los records representan portadores de datos con componentes finales, accesores, igualdad y hash generados. Son superficialmente inmutables: si un componente es una lista mutable, su contenido puede cambiar. Una copia defensiva protege la estructura, aunque los elementos también deben evaluarse.

Java 8 incorporó lambdas, Streams y la API temporal moderna. Java 17 incluye records y clases sealed, entre otras características disponibles hasta esa versión. Java 21 estabilizó virtual threads y pattern matching para switch. La versión mínima de cada característica no siempre coincide con la versión donde la conociste.

## Ejemplo

Java 21, declaraciones completas compilables:

```java
import java.util.List;
import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Auditar { String accion(); }

record PedidoVista(long id, List<String> productos) {
    PedidoVista {
        productos = List.copyOf(productos);
    }
}
```

El constructor compacto copia la lista antes de asignarla al componente. El ejemplo no implementa un motor de auditoría.

## En entrevista

**Respuesta breve:** las anotaciones describen metadatos; Lombok genera código; records expresan datos con una API generada y estable.

**Respuesta ampliada:** uso records para DTOs o valores cuando encajan sus reglas. No los equiparo automáticamente con entidades JPA mutables. Antes de una migración reviso JDK, bytecode, bibliotecas, plugins y características preview utilizadas.

## Error frecuente

Creer que Lombok se ejecuta como un servicio en producción o que un record garantiza inmutabilidad profunda de todo su grafo de objetos.

## Práctica

Creá `PedidoVista` desde una `ArrayList`, modificá luego la lista original e intentá modificar la lista devuelta por el record.

### Pista

`List.copyOf` separa la estructura y devuelve una lista no modificable.

### Solución

La modificación original no cambia los productos del record. Agregar a `vista.productos()` lanza `UnsupportedOperationException`. Como los elementos son Strings inmutables, el ejemplo no conserva un elemento mutable compartido.

## Profundización

Para revisar Lombok, observá el código generado o usá delombok. Si la generación oculta reglas del dominio, escribir explícitamente un constructor corto puede comunicar mejor que varias anotaciones.
