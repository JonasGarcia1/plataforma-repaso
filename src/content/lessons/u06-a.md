## Concepto

Una lambda expresa una implementación breve de una interfaz funcional: una interfaz con un único método abstracto relevante. Puede tener métodos `default` y estáticos sin dejar de ser funcional. `@FunctionalInterface` pide al compilador verificar ese contrato; no crea por sí misma comportamiento nuevo.

`Predicate<T>` recibe T y devuelve boolean; `Function<T,R>` transforma T en R; `Supplier<T>` produce un valor sin recibir argumentos; `Consumer<T>` recibe un valor y no devuelve resultado. `UnaryOperator<T>` transforma un T en otro T. Elegí la forma según la operación en lugar de memorizar nombres aislados.

Las referencias a métodos, como `Pedido::total`, permiten reutilizar un método donde se espera una función compatible. Las lambdas pueden capturar variables locales finales o efectivamente finales. Eso evita reasignar la variable capturada, pero no vuelve inmutable el objeto al que apunta.

## Ejemplo

Java 21 ejecutable como `Reglas.java`:

```java
import java.util.function.*;
class Reglas {
    record Pedido(int unidades, boolean confirmado) {}
    public static void main(String[] args) {
        Predicate<Pedido> tieneUnidades = p -> p.unidades() > 0;
        Predicate<Pedido> confirmado = Pedido::confirmado;
        Predicate<Pedido> despachable = tieneUnidades.and(confirmado);
        Function<Pedido, String> resumen = p -> p.unidades() + " unidades";
        Supplier<Pedido> borrador = () -> new Pedido(1, false);
        Pedido pedido = borrador.get();
        System.out.println(resumen.apply(pedido));
        System.out.println(despachable.test(pedido)); // false
    }
}
```

Las funciones pequeñas pueden probarse por separado. Componer reglas conserva su nombre e intención, algo que se pierde en una condición enorme escrita directamente en un controlador.

## En entrevista

**Respuesta breve:** una lambda implementa un contrato funcional y permite pasar comportamiento como argumento.

**Respuesta ampliada:** uso predicados para condiciones y funciones para transformaciones. Intento que las reglas de cálculo sean puras: mismo resultado para la misma entrada y sin modificar estado externo. Java permite efectos en lambdas; el estilo funcional no los prohíbe automáticamente.

## Error frecuente

Creer que una lambda implica ejecución paralela o diferida por sí sola. Quien recibe la función decide cuándo, cuántas veces y en qué hilo la invoca.

## Práctica

Componé una regla que permita despachar pedidos confirmados con entre 1 y 5 unidades, ambas inclusive.

### Pista

Podés agregar otro predicado mediante `and`.

### Solución

`despachable.and(p -> p.unidades() <= 5)` mantiene la condición inferior ya definida. Probá 0, 1, 5 y 6 unidades, además de un pedido sin confirmar. Los bordes muestran errores que un único caso feliz no detecta.

## Profundización

`Predicate.and` y `or` cortocircuitan. Si el primer predicado decide el resultado, el segundo puede no ejecutarse. Por eso no conviene depender de efectos secundarios escondidos dentro de una condición.
