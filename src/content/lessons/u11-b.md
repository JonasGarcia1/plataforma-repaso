## Concepto

JDBC es la API de Java para trabajar con bases de datos mediante drivers. DataSource entrega conexiones; un pool reutiliza conexiones físicas para evitar abrir una nueva por petición. Cerrar una conexión prestada normalmente la devuelve al pool.

PreparedStatement separa la estructura SQL de sus valores. Esto reduce el riesgo de SQL injection cuando se parametrizan todos los datos. Los placeholders no sirven para nombres de tabla o columnas; si el usuario elige un criterio de ordenamiento, se necesita una lista permitida.

Los recursos tienen un ciclo de vida: Connection, PreparedStatement y ResultSet deben cerrarse incluso si falla la operación. try-with-resources lo expresa de manera segura. Las credenciales y URL de conexión pertenecen a configuración, nunca al código de ejemplo versionado.

## Ejemplo

Fragmento parcial Java 21 con java.sql y javax.sql.DataSource; requiere driver, pool y esquema configurados:

```java
String sql = "SELECT stock FROM productos WHERE sku = ?";
try (Connection connection = dataSource.getConnection();
     PreparedStatement query = connection.prepareStatement(sql)) {
    query.setString(1, sku);
    try (ResultSet rows = query.executeQuery()) {
        if (rows.next()) {
            int stock = rows.getInt("stock");
            System.out.println(stock);
        }
    }
}
```

sku se envía como valor, aunque contenga comillas. No se concatena a la consulta. Para modificar filas usaríamos executeUpdate y revisaríamos la cantidad afectada.

## En entrevista

**Breve:** PreparedStatement parametriza valores y try-with-resources garantiza liberación de recursos.

**Ampliada:** configuraría límites del pool y timeouts según capacidad de la base. Más conexiones no siempre significan más rendimiento: pueden aumentar contención y saturar el servidor.

## Error frecuente

Concatenar un parámetro dentro del SQL y luego crear un PreparedStatement. El nombre de la clase no arregla una consulta ya construida de forma insegura.

## Práctica

Reescribí: SELECT * FROM productos WHERE sku = ' más la entrada del usuario. Indicá qué hacer si la consulta no devuelve filas.

### Pista

La ausencia del producto es un resultado de negocio, no necesariamente una excepción SQL.

### Solución

Usá WHERE sku = ?, asigná con setString y comprobá rows.next(). Devolvé Optional o un resultado explícito del repositorio. Separá producto ausente de fallo de conexión y evitá exponer mensajes del driver al cliente.

## Profundización

Con autocommit desactivado, agrupá escrituras con commit y ejecutá rollback ante fallos. No mantengas una conexión abierta mientras esperás una API remota. El pool debe restablecer el estado de las conexiones y la aplicación debe definir claramente quién controla cada transacción.
