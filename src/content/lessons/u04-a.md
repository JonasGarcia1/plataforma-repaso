## Concepto

Big O describe cómo crece el costo al crecer la entrada. Acceder a un índice de array cuesta O(1); recorrerlo cuesta O(n); dos recorridos anidados completos suelen costar O(n²). No es un cronómetro: constantes, memoria y distribución de los datos también importan. Separá costo temporal de espacio auxiliar.

La búsqueda lineal revisa hasta n elementos y sirve sin orden previo. La búsqueda binaria descarta aproximadamente la mitad en cada paso y requiere un array ordenado según el mismo criterio; cuesta O(log n). Ordenar solamente para hacer una búsqueda aislada puede costar más que buscar linealmente.

La pregunta original pide fusionar dos arrays ya ordenados recorriendo cada uno una sola vez. Concatenar y luego ordenar no cumple esa consigna. Dos índices permiten elegir siempre el menor elemento pendiente: cada valor se consume una vez, en O(n+m), y la salida ocupa O(n+m).

## Ejemplo

Java 21, clase completa compilable; llamá `Fusion.unir` desde un `main` o JShell:

```java
class Fusion {
    static int[] unir(int[] a, int[] b) {
        int[] resultado = new int[a.length + b.length];
        int i = 0, j = 0, k = 0;
        while (i < a.length && j < b.length) {
            resultado[k++] = a[i] <= b[j] ? a[i++] : b[j++];
        }
        while (i < a.length) resultado[k++] = a[i++];
        while (j < b.length) resultado[k++] = b[j++];
        return resultado;
    }
}
```

Para `[1,3,5,9]` y `[2,6,8]`, el resultado es `[1,2,3,5,6,8,9]`. Los bucles finales consumen solamente la porción restante; no vuelven a recorrer entradas completas.

## En entrevista

**Respuesta breve:** identifico tamaño de entrada, operación dominante y memoria adicional, aclarando las precondiciones.

**Respuesta ampliada:** en la fusión mantengo como invariante que la salida construida está ordenada y contiene los menores elementos ya consumidos. Elegir el menor de las dos cabeceras preserva esa propiedad. No elimino duplicados salvo que se solicite.

## Error frecuente

Decir que todo bucle anidado es O(n²). Un bucle interior que divide un contador por dos puede cambiar la complejidad; importan los recorridos reales.

## Práctica

Probá la fusión con una entrada vacía, números repetidos y negativos. Indicá qué pasa si una entrada viene desordenada.

### Pista

Las precondiciones forman parte del contrato.

### Solución

`[]` y `[2]` devuelve `[2]`; `[-2,1,1]` y `[-1,1]` devuelve `[-2,-1,1,1,1]`. Una entrada desordenada puede producir salida incorrecta. Podés documentar orden como precondición o validarlo con un recorrido adicional, que mantiene O(n+m) pero cambia la restricción estricta de una sola pasada.

## Profundización

En búsqueda binaria usá `medio = inicio + (fin - inicio) / 2` para evitar overflow en la suma. El acceso rápido por índice es parte de su eficiencia: una lista enlazada no ofrece la misma ventaja.
