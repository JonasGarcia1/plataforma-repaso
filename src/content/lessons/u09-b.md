## Concepto

Java SE aporta el lenguaje y sus bibliotecas generales. Java EE agrupaba especificaciones para aplicaciones empresariales; su evolución continúa como Jakarta EE. Una especificación define contratos y una implementación los ejecuta: Jakarta Servlet define la API web y un contenedor como Tomcat atiende conexiones y gestiona su ciclo de vida.

Jakarta EE 9 cambió muchas APIs empresariales de javax a jakarta. Eso no significa reemplazar todos los paquetes javax: javax.sql.DataSource sigue perteneciendo al entorno Java. Spring Boot 3 usa Spring Framework 6 y APIs Jakarta; los ejemplos de este curso se sitúan allí con Java 21.

Un Servlet procesa solicitudes mediante métodos como doGet. El contenedor suele reutilizar la misma instancia para muchas peticiones concurrentes. Por ello, datos específicos de un usuario no deben almacenarse en atributos mutables del Servlet.

## Ejemplo

Fragmento parcial Java 21 con Jakarta Servlet; requiere dependencia Servlet y contenedor configurados:

```java
@WebServlet("/health")
public class HealthServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest request,
                         HttpServletResponse response)
            throws IOException {
        response.setStatus(HttpServletResponse.SC_OK);
        response.setContentType("text/plain;charset=UTF-8");
        response.getWriter().write("ok");
    }
}
```

En un proyecto Boot con Servlet embebido, el escaneo de @WebServlet requiere configuración explícita, por ejemplo @ServletComponentScan. Un controller MVC normalmente evita registrar Servlets propios.

## En entrevista

**Pregunta:** ¿Cómo se relacionan Jakarta EE y Spring?

**Breve:** Jakarta EE es un conjunto de especificaciones; Spring es un ecosistema que utiliza algunas de ellas.

**Ampliada:** Spring MVC se apoya en Servlet mediante DispatcherServlet. Este coordina el enrutamiento hacia controladores y la conversión de respuestas. Boot facilita el arranque y la configuración; no reemplaza HTTP ni el contenedor.
## Error frecuente

Creer que todo proyecto Spring necesita desplegar un WAR en un servidor externo, o que Spring implementa toda la plataforma Jakarta EE.

## Práctica

Un Servlet guarda el email de la petición en un atributo de instancia y luego lo imprime. Identificá el riesgo y corregí el diseño.

### Pista

Dos solicitudes pueden ejecutar doGet al mismo tiempo.

### Solución

Usá una variable local obtenida del request. El atributo compartido puede ser sobrescrito por otra petición y filtrar datos entre usuarios. No hace falta sincronizar todo el Servlet si evitamos ese estado compartido.

## Profundización

Los filtros interceptan solicitudes y respuestas para tareas transversales. Los interceptores MVC trabajan dentro del flujo de Spring MVC. No tienen exactamente el mismo punto de ejecución ni sustituyen automáticamente a los filtros de seguridad.
