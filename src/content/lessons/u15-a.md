## Concepto

EDA organiza colaboración mediante eventos: hechos que ya ocurrieron, como PedidoCreado. Un productor publica y uno o más consumidores reaccionan. Esto desacopla el momento de ejecución, pero exige comprender demoras, duplicados y fallos.

Kafka conserva registros en topics divididos en particiones. Cada registro recibe un offset dentro de su partición. La clave orienta la elección de partición; los registros de una partición mantienen orden. No hay un orden global automático entre todas las particiones.

Un consumer group reparte particiones entre sus consumidores. Grupos diferentes leen de forma independiente: Inventario y Notificaciones pueden recibir el mismo pedido. Dentro de un grupo, una partición se asigna a un consumidor a la vez bajo el modelo habitual. Con tres particiones, un cuarto consumidor no aumenta el paralelismo de lectura de ese topic en ese grupo.

## Ejemplo

Fragmento parcial Java 21 / Spring Kafka; evento, serializadores y broker configurados:

```java
kafkaTemplate.send(
    "orders.created.v1",
    event.orderId().toString(),
    event
);

@KafkaListener(
    topics = "orders.created.v1",
    groupId = "inventory-service")
void recibir(OrderCreatedEvent event) {
    inventario.reservar(event);
}
```

El laboratorio usa orderId como key y grupos diferentes para inventario y notificaciones. Enviar es asíncrono: hay que tratar el resultado de publicación y sus fallos.

## En entrevista

**Pregunta:** ¿Qué aportan las particiones y los grupos de consumidores en Kafka?

**Breve:** particiones aportan paralelismo y orden local; grupos permiten repartir trabajo o consumir independientemente.

**Ampliada:** elegiría clave según la entidad cuyo orden necesito mantener. Monitorearía lag y procesamiento, y definiría el momento de confirmar offsets según las garantías requeridas.
## Error frecuente

Suponer que dos instancias del mismo grupo reciben ambas todos los eventos, o que Kafka elimina un mensaje en cuanto un consumidor lo lee.

## Práctica

Un topic tiene tres particiones. Inventario usa dos instancias en un grupo y Notificaciones una instancia en otro. ¿Cuántos servicios reciben cada registro y cómo se reparte el trabajo?

### Pista

Separá independencia entre grupos de asignación dentro del grupo.

### Solución

Cada grupo puede procesar el registro: una de las instancias de Inventario y la de Notificaciones. Las tres particiones se distribuyen entre las dos instancias de Inventario; la asignación exacta depende del asignador.
