## Concepto

Una interfaz expresa un contrato que varias clases pueden cumplir. Una clase abstracta permite combinar ese contrato con estado, constructores y comportamiento compartido. Java admite extender una sola clase e implementar varias interfaces. Las interfaces pueden tener métodos `default`, estáticos y privados; no son únicamente listas de métodos vacíos.

Polimorfismo permite invocar un contrato y ejecutar la implementación correspondiente al objeto real. Sobrescribir redefine un método heredado compatible; sobrecargar declara métodos del mismo nombre con parámetros diferentes. La sobrecarga se resuelve usando tipos conocidos en compilación; el despacho de métodos de instancia sobrescritos ocurre en ejecución. Campos y métodos estáticos no participan igual en ese despacho.

La abstracción elige qué aspectos importan para el problema. Un notificador puede ocultar autenticación y formato sin ocultar que enviar mensajes puede fallar. La igualdad también es un contrato: dos pedidos con igual monto no necesariamente son el mismo pedido.

## Ejemplo

Java 21, declaraciones completas compilables juntas; fragmento de dominio sin `main`:

```java
interface Notificador {
    void enviar(String mensaje);
}

class NotificadorConsola implements Notificador {
    @Override public void enviar(String mensaje) {
        System.out.println(mensaje);
    }
}

class ConfirmarPedido {
    private final Notificador notificador;
    ConfirmarPedido(Notificador notificador) {
        this.notificador = notificador;
    }
    void confirmar(long id) {
        notificador.enviar("Pedido " + id + " confirmado");
    }
}
```

`ConfirmarPedido` puede recibir otra implementación sin cambiar su lógica. Eso es útil para pruebas y para adaptarse a proveedores distintos.

## En entrevista

**Pregunta:** ¿Cuándo elegirías una interfaz y cuándo una clase abstracta?

**Breve:** una interfaz describe capacidades; una clase abstracta también puede compartir estado y construcción entre subtipos relacionados.

**Ampliada:** elegiría una interfaz para un puerto de notificación y composición para sus colaboradores. Reservaría la clase abstracta para una familia con invariantes compartidas reales. `@Override` ayuda al compilador a detectar firmas que no sobrescriben lo esperado.
## Error frecuente

Decir que la superclase sobrescribe a la subclase: ocurre al revés. El retorno puede ser covariante; no necesita ser idéntico si es un subtipo permitido.

## Práctica

Necesitás registrar mensajes en una prueba, sin imprimir. ¿Cómo cambiás el diseño?

### Pista

El consumidor ya depende de una interfaz.

### Solución

Creá un `NotificadorMemoria` que implemente `enviar` agregando el texto a una lista interna. Inyectalo al construir `ConfirmarPedido` y verificá el mensaje capturado. No necesitás agregar condiciones de «modo test» al caso de uso.

## Profundización

El principio de sustitución requiere respetar comportamiento observable, no solo compilar. Una implementación que rechaza cualquier mensaje válido cumple la firma pero rompe las expectativas del consumidor. Documentá precondiciones y fallos del contrato.
