## Concepto

`CompletableFuture` representa un resultado que llegará más adelante y permite componer etapas. `thenApply` transforma un resultado; `thenCompose` encadena otra operación asíncrona; `thenCombine` junta resultados independientes. Las variantes `Async` pueden ejecutar en otro executor; especificarlo evita depender accidentalmente de recursos globales compartidos.

Los virtual threads de Java 21 son hilos ligeros administrados por la JVM, útiles para gran cantidad de tareas que esperan I/O. Permiten escribir código bloqueante con alta concurrencia. No hacen más rápida una operación intensiva de CPU ni aumentan conexiones disponibles en una base de datos. Hay que limitar el acceso al recurso escaso, no solo contar hilos.

Definí timeout, manejo de errores y presupuesto de concurrencia. Un timeout de CompletableFuture puede completar el futuro excepcionalmente sin detener la operación subyacente. El cliente HTTP, driver o protocolo también necesita límites y una política de cancelación apropiada.

## Ejemplo

Java 21 ejecutable como `Componer.java`; simula dos cálculos independientes, sin red:

```java
import java.util.concurrent.*;
class Componer {
    public static void main(String[] args) {
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            var stock = CompletableFuture.supplyAsync(() -> 4, executor);
            var precio = CompletableFuture.supplyAsync(() -> 250, executor);
            var resumen = stock.thenCombine(precio,
                (unidades, centavos) -> unidades * centavos)
                .orTimeout(2, TimeUnit.SECONDS);
            System.out.println(resumen.join()); // 1000
        }
    }
}
```

`join` espera y envuelve errores con excepciones unchecked. `get` tiene otro contrato de excepciones, incluyendo interrupción. Elegí conscientemente dónde bloqueás para recoger el resultado.

## En entrevista

**Respuesta breve:** CompletableFuture compone resultados; virtual threads permiten muchas tareas bloqueantes con menor costo por hilo.

**Respuesta ampliada:** para consultar precio y stock en paralelo verifico independencia y tolerancia a fallos. Si falta un precio no devolvería cero como si fuera válido; representaría el fallo. Mido saturación de dependencias y aplico límites, por ejemplo con un semáforo.

## Error frecuente

Crear un pool de virtual threads para reutilizarlos como si fueran platform threads costosos. El modelo habitual es uno por tarea; las conexiones y otras dependencias mantienen sus propios límites.

## Práctica

La consulta de precio tarda diez segundos y el futuro tiene timeout de dos. ¿Qué garantiza ese timeout y qué falta configurar?

### Pista

No confundas el estado del resultado con la vida de la petición remota.

### Solución

El futuro puede quedar fallido a los dos segundos, pero la llamada puede seguir ocupando recursos. Configurá tiempos de conexión y lectura en el cliente, cancelación cuando esté soportada y límites de solicitudes concurrentes. El cierre del executor también puede esperar tareas pendientes.

## Profundización

En Java 21 hay situaciones de pinning durante ciertas operaciones bloqueantes dentro de monitores, entre otras. Revisá el comportamiento de la versión desplegada y medí antes de migrar sincronización indiscriminadamente; las implementaciones evolucionan entre versiones.
