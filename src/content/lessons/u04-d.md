# Patrones de algoritmos para entrevistas

## Concepto

Antes de escribir un doble bucle, nombrá la operación dominante y verificá si la ventana puede avanzar sin volver atrás. Un mapa mantiene frecuencias y una pila conserva el último elemento pendiente. El patrón no sustituye la comprensión del problema: solo evita empezar desde cero.

Pensalo con un pedido, inventario o notificación: los datos y las dependencias cambian, pero el límite correcto permite comprobar qué parte tomó una decisión. La meta no es memorizar una API, sino explicar el contrato, el costo y el riesgo de la alternativa elegida. Cuando una regla depende de infraestructura, dejá visible qué asume el código y qué debe verificar el entorno.

## Ejemplo

Una ventana deslizante conserva un intervalo [izquierda, derecha]. Al agregar el carácter derecho se actualiza el contador; si la regla se rompe, se avanza izquierda hasta restaurarla. Cada puntero avanza a lo sumo n veces, por eso el recorrido es O(n).

```java
import java.util.HashMap;
import java.util.Map;

public class VentanaUnica {
  static int maximaSinRepetidos(String texto) {
    Map<Character, Integer> ultima = new HashMap<>();
    int izquierda = 0, mejor = 0;
    for (int derecha = 0; derecha < texto.length(); derecha++) {
      char actual = texto.charAt(derecha);
      izquierda = Math.max(izquierda, ultima.getOrDefault(actual, -1) + 1);
      ultima.put(actual, derecha);
      mejor = Math.max(mejor, derecha - izquierda + 1);
    }
    return mejor;
  }
  public static void main(String[] args) { System.out.println(maximaSinRepetidos("abba")); }
}
```

El fragmento es ilustrativo salvo en la lección de algoritmos, cuyo ejemplo es una clase Java 21 completa. En producción, los nombres, errores y límites se ajustan al contrato del módulo y se prueban con entradas normales y de borde.

## En entrevista

Una respuesta breve sería: “two pointers, sliding window, mapas de frecuencia y pilas se usa para tomar una decisión explícita y verificable; primero aclaro el contrato, luego indico el costo y finalmente describo qué haría ante un fallo o un dato inesperado”. Una respuesta ampliada debe sumar un ejemplo concreto, una alternativa descartada y el límite que evita prometer garantías que la herramienta no ofrece.

## Error frecuente

Decir que HashMap siempre es O(1) sin mencionar que es costo promedio y que la entrada puede tener casos límite. También es frecuente olvidar cadena vacía, repetidos, un único elemento y valores negativos.

La corrección empieza por observar evidencia: entradas, resultado esperado, dependencia involucrada y métrica o prueba que puede demostrar el cambio. Evitá agregar complejidad si una regla local, un contrato mejor definido o una consulta medida resuelve el problema.

## Práctica

Para cada arreglo o texto, escribí primero la precondición, luego el invariante y finalmente tiempo y espacio. Si una solución requiere ordenar, aclaralo: ordenar cambia el costo y puede perder el orden original.

Consigna: Resuelve la longitud máxima de una subcadena sin caracteres repetidos. Probá "", "a", "abba" y "abcabcbb".

### Pista

Escribí primero qué debe mantenerse verdadero mientras avanza el proceso. Enumerá al menos dos casos límite y anotá el tiempo y espacio de la solución antes de implementar. Si interviene una dependencia externa, definí qué ocurre ante timeout, dato inválido o reinicio.

### Solución

Usá un Map<Character, Integer> con la última posición. Cuando un carácter ya pertenece a la ventana, mové izquierda al máximo entre su valor actual y la posición previa más uno. Medí derecha - izquierda + 1 en cada paso.

Comprobá la solución con un caso feliz, un borde y una entrada inválida. Si el resultado afecta otra capa, agregá una aserción en esa frontera en lugar de confiar únicamente en una inspección manual.

## Profundización

Compará la versión con ventana contra una versión de fuerza bruta. La segunda sirve como oráculo para entradas chicas; la primera demuestra el patrón y justifica O(n) tiempo y O(k) espacio, donde k es la cantidad de caracteres distintos.

Relacioná este tema con una lección previa y con una posterior: una buena explicación muestra cómo una decisión local cambia el comportamiento del sistema completo. Documentá la hipótesis, medí el resultado y revisá la decisión cuando cambien los datos o las restricciones.
