## Concepto

Una clase define estado y comportamiento; un objeto es una instancia con identidad propia. Encapsular consiste en proteger reglas, no solamente en agregar getters y setters. Si el inventario nunca debe ser negativo, todos sus caminos de modificación deben respetarlo.

El constructor deja al objeto en un estado válido. En Java 21, `this(...)` delega en otro constructor de la misma clase y `super(...)` en el de la clase padre, como primera instrucción. Los modificadores delimitan acceso: `private` restringe al ámbito de la clase; sin modificador se permite el paquete; `protected` agrega acceso por herencia con reglas particulares; `public` expone el miembro.

`static` pertenece a la clase; un campo normal pertenece a cada objeto. `final` impide reasignar una variable, sobrescribir un método o extender una clase, según dónde se use. Una referencia final a una lista todavía puede permitir agregar elementos. Los inicializadores estáticos se ejecutan durante la inicialización de la clase, que no equivale necesariamente al momento de cargarla.

## Ejemplo

Java 21, clase completa sin `main`; compilable como `Inventario.java`:

```java
class Inventario {
    private final String sku;
    private int disponible;

    Inventario(String sku, int disponible) {
        if (sku == null || sku.isBlank() || disponible < 0) {
            throw new IllegalArgumentException("Inventario inválido");
        }
        this.sku = sku;
        this.disponible = disponible;
    }

    void reservar(int cantidad) {
        if (cantidad <= 0 || cantidad > disponible) {
            throw new IllegalArgumentException("Cantidad no reservable");
        }
        disponible -= cantidad;
    }

    int disponible() { return disponible; }
    String sku() { return sku; }
}
```

No exponemos un setter que permita ignorar la regla de reserva. Este ejemplo es secuencial; la concurrencia requiere protección adicional.

## En entrevista

**Respuesta breve:** encapsulación mantiene invariantes detrás de una API pequeña y un constructor válido.

**Respuesta ampliada:** prefiero métodos con intención del negocio, como `reservar`, a modificaciones arbitrarias. Usaría `static` para funciones sin estado de instancia; evitaría convertir información de cada pedido en estado global compartido.

## Error frecuente

Confundir una clase con un objeto. Dos instancias tienen sus propios campos de instancia, pero comparten los campos estáticos de esa clase cargada.

## Práctica

Agregá una operación para reponer stock evitando cantidades negativas y desbordamiento.

### Pista

Validá primero y usá aritmética que detecte overflow.

### Solución

Un método `reponer(int cantidad)` rechaza `cantidad <= 0`, calcula `Math.addExact(disponible, cantidad)` y recién entonces asigna. Si el cálculo falla, el estado previo permanece intacto.

## Profundización

Herencia expresa una relación de sustitución, no una herramienta automática para reutilizar líneas. La composición suele permitir cambiar una política de reservas sin heredar todo el estado del inventario.
